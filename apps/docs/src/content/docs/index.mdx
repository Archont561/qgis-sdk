  <Card title="One declaration, every host" icon="puzzle">
    `@plugin`, `@action` and a `Dialog` or `Dock` built from the UI catalogue
    describe the plugin once. QGIS gets `metadata.txt` and a `classFactory`
    from `build`; a web page gets a typed `QgisSdk` from the same declarations.
  </Card>
  <Card title="Testable without QGIS" icon="approve-check">
    The declarations, the contract layer and the UI catalogue are standard
    library only. `qgis-sdk test` runs a project on the SDK fakes; `--target
    qgis` and `--target desktop` add the native layers when a QGIS is there.
  </Card>
  <Card title="Processing, layers, files, jobs" icon="setting">
    `ctx` reaches layers, the Processing registry (any provider, typed
    parameters), files the user granted, settings, the network, the log and
    scoped background jobs - each service with a fake for tests.
  </Card>
  <Card title="Web views as first-class surfaces" icon="laptop">
    A `QWebEngineView` page talks to the plugin over an allowlisted bridge:
    `QgisSdk.fromBridgeSchema(schema)`, framework-free stores, React, Vue and
    Svelte bindings, and `qgis-sdk-ui` light-DOM components.
  </Card>
</CardGrid>

## From an empty directory to an installable ZIP

<ol class="steps">
  <li>
    **Install** the developer kit: `pip install qgis-sdk` brings the runtime a
    plugin imports and the `qgis-sdk` command.
  </li>
  <li>
    **Scaffold and check**: `qgis-sdk new my_tools --title "My Tools"`, then
    `qgis-sdk check` - pyproject, syntax, imports, UI rules, runtime version.
  </li>
  <li>
    **Test and run**: `qgis-sdk test` without QGIS, `qgis-sdk dev` inside a
    real QGIS Desktop with reload on save.
  </li>
  <li>
    **Build**: `qgis-sdk build` writes `dist/<plugin>-<version>.zip` with the
    runtime vendored inside - nothing to install on the user's QGIS.
  </li>
</ol>
