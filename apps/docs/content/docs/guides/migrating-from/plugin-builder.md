title: Migrating from Plugin Builder to the QGIS SDK
description: Move a Plugin Builder-generated plugin onto the SDK's declaration model, step by step - about an hour for a medium plugin.
---

This page is for a plugin that Plugin Builder generated and you have since
grown: `metadata.txt` edited by hand, a `<name>_dialog.py` full of widgets wired
to `iface`, a `Makefile` that assembles the ZIP. The SDK replaces the scaffolding
around your code, not your code.

## What maps to what

| Plugin Builder artifact | SDK equivalent |
| :-- | :-- |
| `metadata.txt`, hand-maintained (author, version, `hasProcessingProvider`) | rendered by `qgis-sdk build` from `[tool.qgis-sdk]` in `pyproject.toml` and the plugin declaration |
| `<name>.py` with `classFactory` and `initGui` | `QgisSdkPlugin(id=..., title=...)` in `<name>/plugin.py`; the entry point is generated |
| Dialog subclass in `<name>_dialog.py` | an `@app.surface` class (`Dialog`, `Dock`) built from declared fields |
| `iface.addToolBarIcon(...)`, `iface.addPluginToMenu(...)` | `@toolbar(...)`, `@menu(...)`, `@shortcut(...)` stacked on the action |
| `iface.messageBar().pushMessage(...)` | `ctx.notifications.warning/success(...)` |
| `QgsProject.instance()` lookups | `ctx.project`, `ctx.layers` |
| `Makefile` (zip, compile) | `qgis-sdk build` |
| `test/` with a mocked `QgsApplication` | `qgis-sdk test`, whose fakes come with the kit |

## Step by step

1. Scaffold the new project **beside** the old plugin, so both stay runnable
   while you port:

   ```sh
   qgis-sdk new field_tools --title "Field tools" --no-input
   cd field_tools
   ```

2. Point `pyproject.toml` at the declaration and state the QGIS floor:

   ```toml
   [tool.qgis-sdk]
   plugin = "field_tools.plugin:app"
   qgis-minimum-version = "4.0"
   hosts = ["desktop"]
   ```

3. Move each dialog action into `plugin.py` as an `@app.action`, and delete the
   `iface` plumbing it used to need:

   ```python
   from qgis_sdk import QgisSdkPlugin, toolbar
   from qgis_sdk.core import PluginContext
   from qgis_sdk.models import VectorLayerInfo

   app = QgisSdkPlugin(id="field_tools", title="Field tools")

   @toolbar(icon="buffer.svg", text="Buffer")
   @app.action(id="buffer", title="Buffer in a projected CRS")
   def buffer(ctx: PluginContext, layer_id: str, distance_metres: float) -> VectorLayerInfo:
       ...
   ```

4. Rebuild the dialog as a surface. Fields come from the action's schema, so
   the widget code that mirrored the parameters goes away:

   ```python
   from qgis_sdk import menu
   from qgis_sdk.ui import Button, Column, Dialog, Form, on

   @app.surface
   @menu("Plugins/Field tools")
   class BufferDialog(Dialog):
       title = "Buffer a layer"

       def build(self) -> Column:
           self.form = Form.for_action(self.ctx, "buffer")
           return Column("buffer_dialog", [self.form, Button("run", "Buffer")])

       @on("run").clicked
       def run(self) -> None:
           self.ctx.actions.buffer(**self.form.submit())
   ```

5. Replace the mocked-QGIS tests with the kit's fakes and run them:

   ```sh
   qgis-sdk test        # no QGIS needed
   qgis-sdk check       # declaration and metadata codes
   qgis-sdk dev         # loads it into a running QGIS Desktop
   qgis-sdk build       # dist/field_tools-<version>.zip
   ```

6. Delete what the SDK now owns: `metadata.txt`, the `Makefile`, `resources.qrc`
   and the generated entry point. Keep the icons - they belong in the package's
   `icons/` directory, because `@toolbar(icon=...)` resolves them from there.

## Before and after

```python
# before: field_tools.py, generated by Plugin Builder and edited since
class FieldTools:
    def __init__(self, iface):
        self.iface = iface

    def initGui(self):
        self.action = QAction("Buffer", self.iface.mainWindow())
        self.action.triggered.connect(self.run)
        self.iface.addToolBarIcon(self.action)
        self.iface.addPluginToMenu("&Field tools", self.action)

    def run(self):
        layer = self.iface.activeLayer()
        if layer is None:
            self.iface.messageBar().pushWarning("Field tools", "select a layer")
            return
        ...
```

```python
# after: field_tools/plugin.py, the whole placement is the decorators
app = QgisSdkPlugin(id="field_tools", title="Field tools")

@toolbar(icon="buffer.svg", text="Buffer")
@app.action(id="buffer", title="Buffer in a projected CRS")
def buffer(ctx: PluginContext, layer_id: str, distance_metres: float) -> VectorLayerInfo:
    return LocalGisWorkflow(ctx).buffer(layer_id, distance_metres)
```

## Gotchas

- An action that takes inputs cannot be run from a button; place its surface
  instead. `qgis-sdk check` reports `UI003` rather than guessing.
- `iface` is never serialised. Anything a handler needs, it reads from `ctx` -
  that is what makes the same handler testable without QGIS.
- `metadata.txt` becomes build output. Editing it in the project has no effect
  on the ZIP.
- The trigger rule still applies to a surface: a placed action for a surface
  opens it, so keep one surface per dialog you used to open by hand.
