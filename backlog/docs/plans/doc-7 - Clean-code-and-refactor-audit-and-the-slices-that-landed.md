# Clean-code and refactor audit, and the slices that landed

Audited on 2026-10-21 against `.agents/skills/clean-code-principles/SKILL.md` (finding
format and priority table) and `.agents/skills/refactor/SKILL.md` (golden rules, smell
catalogue, checklist). Method was measurement, not impression: AST spans for function
and module sizes, identifier-normalised clone detection, and the repository's pinned
`ruff 0.17.1` rule families (`C901`, `PLR09xx`, `PLR2004`, `SLF001`, `ANN401`,
`ERA001`, `ARG002`, `D1xx`, `TRY003`) run over `src`, `scripts`, `tests` and
`qgis-sdk-release`. Baseline before any edit: 307 passed / 3 skipped, coverage 100.00%,
and the repository's own Ruff and format tasks already clean - so every finding below is
a design observation, not lint debt.

## Landed, one change set each

| Slice | Finding addressed | Verification |
| --- | --- | --- |
| `refactor(sdk): give the safe-integer bound one home` | `[core-dry]` `declarations.py` hardcoded `9007199254740991` twice while `adapters/pydantic_types.py` already named it | `MAX_SAFE_INTEGER` moved to `models` (the QGIS-free leaf both layers already import, so no new edge and no eager-pydantic import); all six generated schemas byte-identical |
| `refactor(sdk): share one schema writer between the two contract examples` | `[core-dry]` `write_schemas()` and the generator CLI existed twice, comment included | one writer in `contract_sample/writing.py`; generated bytes unchanged |
| `refactor(sdk): split the annotation walker into one rule per shape` | `[func-small]`, `[func-single-purpose]` `_schema()` 61 lines at complexity 12; `_describe_action()` 51 lines behind a multi-line negated guard | one function per shape, primitive map built once, three named signature guards; no complexity finding left in `src`; schemas unchanged |
| `docs(sdk): document the scheduler's private handoff protocol` | `[core-encapsulation]` cross-object private calls without a stated contract | `_attach`, `_take`, `_report`, `__await__`, `_suspend_on`, `_settle_on_error`, `_advance`, `_blockers` documented; the audit's own count was corrected - `_release` and `_detach` already had docstrings |
| `test(sdk): split the scheduler suite into one module per guarantee` | `[org-package-cohesion]` 625 lines and 31 concerns in one flat file | stepping, handoff, cancellation and disposal modules; collected node IDs identical (35 before, 35 after), so no test was lost or weakened |
| `refactor(sdk): give each scheduler harness phase its own measurement` | `[func-small]`, `[solid-srp]` `_run_phases()` 208 lines / 106 statements / complexity 16 | heartbeat sampler object plus one function per phase; two live runs before and after report the same 25 keys, the same phase sample counts (1 and 30), the same verdict, blocker text and criteria booleans - only latency digits and thread ids differ; two new tests pin the sampler's offset rule |
| `refactor(release): state one decision per changelog config line` | `[func-small]`, `[name-consistent]`, `[name-searchable]` `parse_versionrc` at complexity 15, `parse_log` overwriting its own loop variable, bare `3` and `2` | old and new parsers diffed side by side over 11 `.versionrc` shapes and 9 git-log shapes, error text included - identical on every case |
| `refactor(sdk): let a report say what an unusable host looks like` | `[core-dry]` plus tautological test: the all-false failure report was spelled out in each harness and restated in each test | `unavailable()` classmethods, the WebEngine error path reduced from a nine-field rebuild to one `replace()`; both failure paths driven directly with a nonexistent prefix still return serialisable reports instead of tracebacks |

Totals: functions over 50 lines repo-wide went from 8 to 3, and no complexity,
magic-value, shadowing or commented-out-code finding remains in shipped source or
scripts. Every slice kept 100.00% coverage and 284 package tests (309 with the
skill-creator suite), and the opt-in harness suite passes at 110 with all four
environment flags set against QGIS `4.2.3-Belém do Pará`.

## Deliberately not changed

- `core/scheduling.py` as a module (538 lines, `Job` 189): the step protocol's invariants
  are why the classes sit together. Splitting them would move eight intra-module private
  calls across a module boundary - more intimacy, not less.
- `_step()` at 8 return statements: a state dispatcher reads better flat, and the returns
  are the states.
- `Adapters` with five constructor parameters, and `Any` in `adapters/webengine.py`:
  injection seams and native pass-through respectively; `Any` is the honest type there.
- `services/contracts.py` one-line protocol members without per-member docstrings: the
  contract sentence is on the class.
- `webengine_smoke.py`'s `ok: bool` signal handler: Qt's signature.
- The 17 `PLR2004` magic values, all in tests: a literal expected value is what keeps an
  assertion independent of the code under test, which is also why `contract_sample` keeps
  its own copy of the safe-integer bound rather than importing the constant that produced it.
- `test_scheduling_properties.py` at complexity 14: the branches are the interleaving
  model of a Hypothesis state test.
- `qgis-sdk-release` `compute_plan()` and `create_release()` at 7 parameters: one internal
  caller each; a parameter object would move the same seven fields without reducing coupling.

## Still open, and not refactoring

Removing `qgis_sdk.hello()` and the bridge's `hello()` is an API decision, not a
behaviour-preserving edit: it is exported from `qgis_sdk/__init__.py`, mirrored in
`qgis-sdk-bridge/src/index.ts`, and documented as intentional in the package README, while
`tests/test_pure_imports.py` already proves the wiring they were standing in for. Same for
the tautological `tests/test_init.py`. A 0.1.0-boundary call, so it is recorded against
TASK-27 rather than taken unilaterally.

Environment note for anyone repeating this: the sandbox reset between sessions dropped
`.pixi` and `node_modules`, restored here with `bash scripts/restore.sh` followed by
`bun install --frozen-lockfile`. That restore still reports the same nine RECORD integrity
mismatches, so the toolchain is an unverified restore and nothing here claims otherwise.
The Conda package build remains blocked by unreachable conda-forge repodata; the wheel and
sdist were built and checked with Twine.
