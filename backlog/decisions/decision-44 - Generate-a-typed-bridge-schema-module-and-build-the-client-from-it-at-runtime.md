## Context

`qgis-sdk bridge generate` renders, per plugin, a `web/src/bridge.ts` of about
three hundred lines: the operation ids, one request and one result interface
per action, a hand-rolled validator per interface, a `QgisSdkContractError`,
and `createOperations(client)` wrapping a `BridgeClient`. The page then needs
`transport.ts` (the QWebChannel `WireTransport`, copied from a template) and
`main.ts` to assemble the three. Everything in that file except the names and
shapes is the same for every plugin, and the shapes are already available as
data: `describe_plugin()` is the version 1 description the file is rendered
from, and `@archont561/qgis-sdk` already parses that description
(`parsePluginDescription`) because the host module validates it.

What the generated file does buy is static type safety - `operations.buffer({
layer_id, distance_metres })` is checked by `tsc`, and a renamed action is a
compile error - which the author asked to keep. A plain `.json` schema import
would lose it: TypeScript sees `Record<string, unknown>` and the page compiles
against any schema.

## Decision

1. **The generated artifact is a typed schema module.** `qgis-sdk bridge
   generate` writes `web/src/bridge.schema.ts`:

   ```ts
   // Generated by qgis-sdk. Do not edit.
   export interface BufferRequest { layer_id: string; distance_metres: number; working_crs: string }
   export interface BufferResult { output: VectorLayerInfo }
   ...
   export interface Operations {
     buffer: { request: BufferRequest; result: BufferResult };
     ...
   }
   export interface Streams { ... }
   export default defineBridgeSchema<Operations, Streams>({
     schema_version: 1, id: "simple", actions: [...], streams: [...],
   });
   export const CONTRACT_FINGERPRINT = "sha256:...";
   ```

   The interfaces are rendered exactly as today, so hovers and errors show
   `BufferRequest`, not a conditional type; `defineBridgeSchema` is an identity
   function whose two type parameters are phantom - they carry the generated
   types onto the runtime description object. The validators and
   `createOperations` are no longer generated.
2. **The client is built from the schema at runtime.** The root export
   `QgisSdk` has one static constructor:

   ```ts
   import { QgisSdk } from "@archont561/qgis-sdk";
   import schema from "./bridge.schema";
   const qgis = QgisSdk.fromBridgeSchema(schema);

   const result = await qgis.buffer({ layer_id, distance_metres: 50, working_crs });
   qgis.progress.subscribe({ data: ... });            // a declared stream
   ```

   `fromBridgeSchema<O, S>(schema: BridgeSchema<O, S>, options?)` returns
   `QgisSdk<O, S>`: one method per action typed `(request: O[K]["request"],
   options?) => Promise<O[K]["result"]>`, one handle per stream, plus
   `client` (the underlying `BridgeClient`) and `close()`. Without
   `options.transport` it connects the QWebChannel `WireTransport` the
   template `transport.ts` built, so that file leaves the scaffold too. The
   generated host module keeps its own shape; this decision is about plugin
   clients.
3. **Validation moves into the package, driven by the schema.** The package
   gains one generic validator for the declaration subset of decision-10
   (primitives, `list`/`tuple`, union, `Literal`, dataclass objects with
   `additionalProperties: false`). `QgisSdkContractError` becomes a package
   class extending `QgisSdkError` with `code: "contract_validation_failed"` -
   the import-free generated copy of decision-40 is no longer needed because
   the generated module imports nothing but the type helper. The schema's
   `schema_version` is checked by `parsePluginDescription` and
   `CONTRACT_FINGERPRINT` by the existing `bindings` drift check.
4. **React and testing follow.** `BridgeProvider` accepts the `QgisSdk`
   instance (or the schema), `useOperation(qgis.buffer)` keeps its signature,
   and `@archont561/qgis-sdk/testing` scripts a host from the same schema so a
   Vitest suite is still network- and QGIS-free.

## Consequences

- A page is three statements away from a typed bridge; the scaffold's
  `main.ts`/`main.tsx` shrink accordingly and `transport.ts` disappears.
- `@archont561/qgis-sdk` 0.4.0 (the m-5 pair) carries `QgisSdk`,
  `defineBridgeSchema`, `BridgeSchema`, the generic validator and
  `QgisSdkContractError` in the root; `BridgeClient`, `WireTransport` and the
  subpaths stay for pages that assemble their own. The wire protocol, the
  plugin-description contract and `HOST_FINGERPRINT` do not change: the same
  description crosses the same channel.
- `qgis-sdk bridge generate --out web/src/bridge.ts` keeps working for one
  minor with a deprecation note; the default output becomes
  `bridge.schema.ts` and the scaffold's `bindings` script points at it. The
  0.6.0 migration note shows the before/after `main.ts`.
- Because the scaffold pins the released bridge (decision-41), the templates
  switch to the three statements in the same release gate that stamps
  `ts-v0.4.0` (TASK-60); inside the repository the example switches on the
  workspace bridge immediately.
- Type-level cost is bounded: no JSON-schema-to-type mapping in the package,
  because the generator still emits the interfaces. A `.json` import is not
  supported as a typed entry; it would compile untyped, which is exactly what
  the author did not want.
