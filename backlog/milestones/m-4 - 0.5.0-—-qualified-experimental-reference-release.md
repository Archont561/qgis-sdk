## Description and exit criteria

Prove the complete local-GIS workflow and clean plugin installation on an
explicit QGIS 4 Windows/Linux x86-64 matrix, with both published artifacts
qualified **as a pair**. Report gaps, migration notes and actual
QGIS/Python/Qt/Chromium evidence; no blanket 4.x or stable-1.0 promise.

Exit criteria, both required:

- **`qgis-sdk`** — the reference workflow runs end to end on the qualified
  matrix, compatibility gates are defined and applied, and the release gate
  records artifacts and checks instead of intent.
- **`@archont561/qgis-sdk-bridge`** — the same workflow's web view runs against
  the published bridge at the milestone version, and the compatibility gate
  names that exact supported pair; any browser-engine or lifecycle limitation
  is recorded as a blocker, not smoothed into a pass.

## Bridge track

This milestone is where the bridge is qualified rather than extended. Three
obligations follow:

- **[TASK-9](../tasks/task-9%20-%20Define-SDK-and-plugin-release-compatibility-gates.md)**
  has to state the pair explicitly: which `qgis-sdk` version a given bridge
  version was tested with, and what a plugin author may assume when they pin
  one. "Same version number" is the working rule
  ([decision-24](../decisions/decision-24%20-%20Release-the-Python-SDK-and-TypeScript-bridge-at-one-shared-version.md)),
  but the gate is what makes it checkable.
- **[TASK-22](../tasks/task-22%20-%20Complete-and-qualify-the-local-GIS-reference-workflow.md)**
  exercises the bridge through a real `QWebEngineView`, which is the first
  evidence that the m-2 transport behaves on the qualified hosts and not only
  under scripted client-local transports.
- Any defect found here is a bridge source change and must be recorded as one:
  it lands in this milestone, gets its own changelog entry, and does not hide
  inside "qualification fixes".

A headless Linux workspace cannot produce the WebEngine rendering or Windows
evidence this milestone needs; those rows stay explicit blockers until the
matrix runs, per the same rule the earlier milestones apply.

## Version policy

0.5.0 is a SemVer planning target, not a published version. Experimental 0.x
breaking changes require a documented minor release; patches are compatible
fixes. Prereleases may use 0.5.0-alpha.1 or 0.5.0-beta.1. Do not bump manifests
during planning. Feature and fix work inside the milestone bumps only the patch;
the minor advances at the milestone close by an explicit `--bump minor`.
`qgis-sdk` and `qgis-sdk-bridge` share **one** package version
([decision-24](../decisions/decision-24%20-%20Release-the-Python-SDK-and-TypeScript-bridge-at-one-shared-version.md));
IPC protocol versions stay independent of it. Stable 1.0.0 requires a later
explicit API-stability decision.
