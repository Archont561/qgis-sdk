## Description and exit criteria

The first minor after the qualified 0.5.0 reference release, cut because two
breaking changes to the author-facing runtime API landed on `main` right after
it and a breaking change in an experimental 0.x line is a documented minor,
not a patch: `@job` became a plain function with the `JobContext` injected
([decision-38](../decisions/decision-38%20-%20Declare-jobs-as-plain-functions-with-the-JobContext-injected.md),
PR #86) and the optional services on every context became capability
attributes that refuse by name, replacing `require_<name>()`
([decision-39](../decisions/decision-39%20-%20Expose-optional-services-as-capability-attributes-that-refuse-by-name.md),
PR #87). Both are already documented in doc-12's 0.6.0 migration notes. The
milestone is the release of what has landed; nothing else is required to join
it, and anything that does join it must keep the migration note honest.

Exit criteria, both required:

- **`qgis-sdk`** — `qgis-sdk-runtime`, `qgis-sdk-tools` and the `qgis-sdk`
  kit are released at 0.6.0 from one green gate (the 0.5.0 gate re-run over
  the new API: Python suite, `tests/scripts`, the example project, the opt-in
  harnesses the changes touched), with the migration note covering every
  removed or renamed name and `qgis-sdk check` still telling a 0.5 project
  what to change.
- **`@archont561/qgis-sdk`** — the bridge is confirmed unaffected: neither
  decision changes what crosses `QWebChannel`, so no file under
  `packages/qgis-sdk-typescript` changes, no npm version is consumed, and
  the plugin-description contract version still agrees across both
  languages. A defect the pair qualification finds is the only thing that
  releases a bridge version.

ran against the 0.6.0 runtime, and `release.py verify-versions` confirms the
contract version agrees in both languages before anything is stamped.

## Version policy

0.6.0 is the next Python minor, not a published version until
[TASK-60](../tasks/task-60%20-%20Prepare-and-qualify-0.6.0-release.md) is
authorised. Experimental 0.x breaking changes require a documented minor
release; patches are compatible fixes. Prereleases may use `0.6.0-rc.N` for a
pipeline rehearsal (dry run, no uploads). Do not bump manifests during
planning. `qgis-sdk` and `@archont561/qgis-sdk` carry **independent** versions,
each derived from its own commits and stamped by its own release tag
([decision-25](../decisions/decision-25%20-%20Version-each-package-independently-behind-a-shared-contract-version.md));
a shared plugin-description contract version is what pairs them. Stable 1.0.0
requires a later explicit API-stability decision.
