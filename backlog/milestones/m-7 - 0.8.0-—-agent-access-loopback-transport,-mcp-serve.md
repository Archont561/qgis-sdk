## Description and exit criteria

Re-pointed on 2026-10-26: `m-7` held the deferred native-compute
reservation at 0.8.0; that moves to 0.9.0 and finally, when the hosts release took that number, to 1.1.0 as [m-12](m-12%20-%201.1.0-%E2%80%94-deferred-native-compute-feasibility-(tenta.md) and the
number goes to a release that ships. [decision-49](../decisions/decision-49%20-%20Expose-the-runtime-to-agents-over-a-loopback-transport-with-the-MCP-server-in-the-tools-for-developers-and-users-alike.md): agents (MCP clients) call a
plugin's declared actions and the curated services through the same
dispatcher, authority and grants the page and the console use. The runtime
gains a stdlib-only loopback transport that speaks the existing envelopes;
the MCP protocol lives in the tools behind the `qgis-sdk-tools[mcp]` extra
on the official `mcp` package; **developer mode** (`qgis-sdk dev --agent`,
`dev.*` tools) and **user mode** (an opt-in Agent access surface in the
built plugin with a consent list and a `uvx` client config) are one server
with two hosts and two grant profiles. Nothing is exposed that the author
did not declare and - in user mode - the user did not tick; the runtime
never binds a non-loopback address and never evaluates code.

Exit criteria, both required:

- **`qgis-sdk`** — `qgis-sdk-runtime`, `qgis-sdk-tools` and the `qgis-sdk`
  kit are released at 0.8.0 from one green gate ([TASK-78](../tasks/task-78%20-%20Prepare-and-qualify-0.8.0-release.md)): the loopback

  audit in the `LogView` and the copied client config ([TASK-76](../tasks/task-76%20-%20Add-user-mode-tool.qgis-sdk.agent-the-generated-Agent-access-surface-consent-audit-and-the-uvx-client-config.md)); the
  scripted MCP client run against both modes; UI snapshots with the
  `dev.ui` tools and the `ui_snapshot` fixture ([TASK-79](../tasks/task-79%20-%20Add-UI-snapshots-structured-tree-plus-screenshot-of-the-plugins-surfaces-dev.ui-agent-tools-and-the-ui_snapshot-fixture.md),
  [decision-51](../decisions/decision-51%20-%20Snapshot-the-plugins-own-surfaces-as-a-structured-tree-plus-screenshot-for-agents-and-tests.md)); the console reaches the same

## Version policy

0.8.0 is the next Python minor after 0.7.0 and is not a published version
until [TASK-78](../tasks/task-78%20-%20Prepare-and-qualify-0.8.0-release.md) is authorised. Experimental 0.x breaking changes require a
documented minor release; patches are compatible fixes. Prereleases may use
`0.8.0-rc.N` for a pipeline rehearsal (dry run, no uploads). Do not bump
manifests during planning. `qgis-sdk`, `@archont561/qgis-sdk` and
`@archont561/qgis-sdk-ui` carry **independent** versions, each derived from
its own commits and stamped by its own release tag ([decision-25](../decisions/decision-25%20-%20Version-each-package-independently-behind-a-shared-contract-version.md)); the two npm
packages are expected not to move in this milestone. Stable 1.0.0 requires a
later explicit API-stability decision.
