## Description and exit criteria

QGIS-free contracts and deterministic declarations, the validator and scheduler
spikes, and the first published **pair**: `qgis-sdk` and
`@archont561/qgis-sdk-bridge` at one version. The milestone is closed —
`v0.1.0` and `v0.1.1` were published on 2026-10-24 and
[TASK-27](../tasks/task-27%20-%20Prepare-and-qualify-0.1.0-release.md) recorded
the gate.

Exit criteria, both met:

- **`qgis-sdk`** — QGIS-free models, services and context contracts; dataclass
  declarations with a generated plugin description; a proven Qt-compatible
  coroutine scheduler and cancellation path.
- **`@archont561/qgis-sdk-bridge`** — the wire primitives a `QWebEngineView`
  consumer needs to read a generated `PluginDescription` and raise the same
  structured errors as Python, without importing browser or Qt globals.

## Bridge track

The 0.1.x bridge is **contract primitives only**, by design
([decision-18](../decisions/decision-18%20-%20Ship-a-framework-neutral-bridge-and-explicit-web-scaffolding-choices.md)):
one framework-neutral package whose root import loads no React, no testing
helper and no `window`, with the transport, generated clients and React helpers
deferred to m-2. What it ships is the TypeScript half of the wire contract — the
same `schema_version: 1` description that Python's `describe_plugin()` produces,
the same stable `code` strings as the Python exceptions, and the same
JavaScript-safe integer bounds as `qgis_sdk.models`.

The bridge runs as its own `ci.yml` job with its own `qgis-sdk-bridge` coverage
flag, and validates checked-in fixture schemas under
`packages/qgis-sdk-bridge/tests/contracts` (hand-declared and
pydantic-generated variants of the run-request/run-result contracts). The
fixtures are not yet proven byte-identical across languages; cross-language
generated-file consistency is a release-gate check, not a 0.1.0 claim.

## Version policy

0.1.0 is a SemVer planning target, not a published version. Experimental 0.x
breaking changes require a documented minor release; patches are compatible
fixes. Prereleases may use 0.1.0-alpha.1 or 0.1.0-beta.1. Do not bump manifests
during planning. `qgis-sdk` and `qgis-sdk-bridge` share **one** package version
([decision-24](../decisions/decision-24%20-%20Release-the-Python-SDK-and-TypeScript-bridge-at-one-shared-version.md));
IPC protocol versions stay independent of it. Stable 1.0.0 requires a later
explicit API-stability decision.
