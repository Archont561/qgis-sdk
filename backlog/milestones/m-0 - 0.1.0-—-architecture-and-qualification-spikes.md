## Description and exit criteria

The foundation release: QGIS-free contracts and deterministic declarations, the
validator and scheduler spikes, and the first published **pair** — `qgis-sdk` and
`@archont561/qgis-sdk` shipped at one number because their surfaces were
built and released together, not because a policy required it. Closed and
published (0.1.0, then 0.1.1 through TASK-27).
The npm package was published as `@archont561/qgis-sdk-bridge` from 0.1.0
through 0.2.0; it is named `@archont561/qgis-sdk` from 0.3.0 on (decision-33),
and this backlog uses the current name throughout.

Exit criteria, both met:

- **`qgis-sdk`** — a six-name package root, QGIS-free models/services/context
  contracts, dataclass declarations that generate the plugin description, and a
  proven Qt-compatible scheduler. Evidence: doc-5 (validator spike), doc-6
  (scheduler spike) and the `v0.1.1` release.
- **`@archont561/qgis-sdk`** — the version-1 wire primitives a web view
  needs in order to read that description and report the same failures as
  Python: `PluginDescription`/`ActionDescription` parsing, safe-integer bounds,
  and the `QgisSdk*` error hierarchy. Published at the same 0.1.x number.

## Bridge track

| Change to `packages/qgis-sdk-typescript` | Task | Resulting bridge version |
| --- | --- | --- |
| `PLUGIN_DESCRIPTION_SCHEMA_VERSION`, `parsePluginDescription`/`parseActionDescription`, `isSafeJsonInteger`/`MAX_SAFE_INTEGER`, the `QgisSdk*` error hierarchy | Python side from TASK-2, published with TASK-27 | 0.1.0, then 0.1.1 |

0.1.x is the only release where the bridge and the SDK carried the same number
for the same reason: both surfaces were written together for the first usable
slice. The bridge's scope stayed deliberately small — parse and bound-check a
`schema_version: 1` description, then throw the SDK's error codes — because
anything larger needs a transport contract, and
[decision-18](../decisions/decision-18%20-%20Ship-a-framework-neutral-bridge-and-explicit-web-scaffolding-choices.md)
requires one package with isolated subpath exports rather than a hand-written
surface added incrementally.

From 0.2.0 the numbers separate
([decision-25](../decisions/decision-25%20-%20Version-each-package-independently-behind-a-shared-contract-version.md));
the shared plugin-description contract version, not the package number, is what
pairs a release.

## Version policy

0.1.0 is a published version, not a planning target. Experimental 0.x breaking
changes require a documented minor release; patches are compatible fixes. The
0.1.1 patch exists for compatible fixes only. `qgis-sdk` and
`@archont561/qgis-sdk` now carry **independent** versions, each derived from its own
commits and stamped by its own release tag
([decision-25](../decisions/decision-25%20-%20Version-each-package-independently-behind-a-shared-contract-version.md)),
which supersedes the paired-number rule this milestone shipped under
([decision-24](../decisions/decision-24%20-%20Release-the-Python-SDK-and-TypeScript-bridge-at-one-shared-version.md)).
Stable 1.0.0 requires a later explicit API-stability decision.
