## Description

Use the shared Python-derived description to support common native UI declarations, QGIS-facing services, and an optional typed WebEngine/TypeScript bridge. Keep handlers and QGIS/Qt behavior in Python.

## Exit criteria

- At least one declared action/form can be rendered and dispatched to a normal Python handler.
- QGIS-specific functionality stays behind Python runtime adapters.
- Web bridge messages use versioned DTOs and an allowlisted operation surface.
- Generic HTTP and typed GIS-service clients share one injectable QGIS-aware transport if included in the v1 service scope.
