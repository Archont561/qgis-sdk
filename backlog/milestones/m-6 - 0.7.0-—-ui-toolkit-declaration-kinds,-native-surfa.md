## Description and exit criteria

Re-pointed on 2026-10-26: 0.7.0 was the tentative native-compute reservation,
which moves to 0.8.0 as [m-7](m-7%20-%200.8.0-%E2%80%94-deferred-native-compute-feasibility-(tenta.md) so milestone ids keep following
release order (doc-10). The number now goes to what the authoring redesign of
[m-5](m-5%20-%200.6.0-%E2%80%94-API-ergonomics-function-jobs-and-capability-attributes.md) leaves wanting: once an author declares actions, algorithms,
bindings and surfaces in one file and a page reaches them through `QgisSdk`,
what the SDK offers *inside* a surface or a page is thin - seven widget
families and one Qt dialog natively, hooks and a bare button on the web.
[decision-46](../decisions/decision-46%20-%20Ship-UI-helpers-as-declaration-kinds-standard-surfaces-headless-web-bindings-and-themed-defaults.md) answers it without a widget kit: parameter kinds that are complete
across every host, three standard surfaces named by actions, headless
bridge-aware web bindings, themed defaults seeded from the QGIS palette, and a
Storybook over the bridge harness that doubles as the Vitest fixtures and
publishes with the docs site ([TASK-43](../tasks/task-43%20-%20Publish-a-Starlight-documentation-site-from-the-backlog-guides.md)).

Exit criteria, both required:

- **`qgis-sdk`** — `qgis-sdk-runtime`, `qgis-sdk-tools` and the `qgis-sdk`
  kit are released at 0.7.0 from one green gate ([TASK-32](../tasks/task-32%20-%20Prepare-and-qualify-0.7.0-release.md)): the new kinds
  ([TASK-68](../tasks/task-68%20-%20Add-file-directory-field-range-colour-and-enum-parameter-kinds-and-the-standard-native-surfaces.md)) describe, render natively, map to Processing parameters and
  cross the wire; `DeclaredForm`, `JobProgressDock` and `LogPanel` open
  through `dialog=`/`dock=`; `ctx.ui.form` and the notification levels work;
  the example uses at least one new kind; doc-12 carries the 0.7.0 notes.
- **`@archont561/qgis-sdk`** — the next bridge minor is released from the same
  gate: the `./react` bindings and Storybook ([TASK-69](../tasks/task-69%20-%20Add-headless-web-bindings-to-.-react-and-a-Storybook-over-the-bridge-harness.md)), the `./ui` themed
  controls with palette seeding ([TASK-70](../tasks/task-70%20-%20Add-themed-.-ui-defaults-seeded-from-the-QGIS-palette.md)), the scaffold templates on them;
  wire, plugin-description contract and `HOST_FINGERPRINT` unchanged, shown
  by `release.py verify-versions` and the fingerprint check. The docs site
  ([TASK-43](../tasks/task-43%20-%20Publish-a-Starlight-documentation-site-from-the-backlog-guides.md)) is live with the Storybook build.

## Version policy

0.7.0 is the next Python minor after 0.6.0 and the bridge takes its next minor
from the same gate; neither is a published version until [TASK-32](../tasks/task-32%20-%20Prepare-and-qualify-0.7.0-release.md) is
authorised. Experimental 0.x breaking changes require a documented minor
release; patches are compatible fixes. Prereleases may use `0.7.0-rc.N` for a
pipeline rehearsal (dry run, no uploads). Do not bump manifests during
planning. `qgis-sdk` and `@archont561/qgis-sdk` carry **independent** versions,
each derived from its own commits and stamped by its own release tag
([decision-25](../decisions/decision-25%20-%20Version-each-package-independently-behind-a-shared-contract-version.md));
a shared plugin-description contract version is what pairs them. Stable 1.0.0
requires a later explicit API-stability decision.
