## Description and exit criteria

Re-pointed on 2026-10-26: 0.7.0 was the tentative native-compute reservation,
which moved to 0.8.0 and then, when agent access took that number, to 0.9.0 as [m-8](m-8%20-%200.9.0-%E2%80%94-deferred-native-compute-feasibility-(tenta.md) so milestone ids keep following
release order (doc-10). The number now goes to what the authoring redesign of
[m-5](m-5%20-%200.6.0-%E2%80%94-API-ergonomics-function-jobs-and-capability-attributes.md) leaves wanting: once an author declares actions, algorithms,
bindings and surfaces in one file and a page reaches them through `QgisSdk`,
what the SDK offers *inside* a surface or a page is thin - seven widget
families and one Qt dialog natively, hooks and a bare button on the web.
[decision-46](../decisions/decision-46%20-%20Ship-UI-helpers-as-declaration-kinds-standard-surfaces-headless-web-bindings-and-themed-defaults.md) answers it without a widget kit: parameter kinds that are complete
across every host, three standard surfaces named by actions, headless
bridge-aware web bindings and themed defaults seeded from the QGIS palette.
[decision-47](../decisions/decision-47%20-%20Build-web-UI-on-a-framework-free-store-core-with-per-framework-adapters-and-ship-components-as-qgis-sdk-ui.md) fixes the web shape: a framework-free store core in the bridge with
React, Vue and Svelte adapters, and the components - web components with
framework wrappers, palette tokens, Storybook - in a third published
artifact, `@archont561/qgis-sdk-ui`. The docs site ([TASK-43](../tasks/task-43%20-%20Publish-a-Starlight-documentation-site-from-the-backlog-guides.md)) goes live in
this milestone and carries the Storybook build.

Exit criteria, all three required:

- **`qgis-sdk`** — `qgis-sdk-runtime`, `qgis-sdk-tools` and the `qgis-sdk`
  kit are released at 0.7.0 from one green gate ([TASK-32](../tasks/task-32%20-%20Prepare-and-qualify-0.7.0-release.md)): the new kinds
  ([TASK-68](../tasks/task-68%20-%20Add-file-directory-field-range-colour-and-enum-parameter-kinds-and-the-standard-native-surfaces.md)) describe, render natively, map to Processing parameters and
  cross the wire; `DeclaredForm`, `JobProgressDock` and `LogPanel` open
  through `dialog=`/`dock=`; `ctx.ui.form` and the notification levels work;
  the example uses at least one new kind; the console reaches the same
  services and plugin handles through `qgis_sdk.console`
  ([TASK-73](../tasks/task-73%20-%20Add-qgis_sdk.console-ConsoleSession-over-the-curated-services-PluginHandle-and-PluginRuntime.algorithms.md), [decision-48](../decisions/decision-48%20-%20Give-the-QGIS-Python-console-the-curated-services-and-plugin-handles-never-iface.md));
  a missing external is a message-bar error, not a traceback, and pure-Python
  packages vendor through `build` ([TASK-77](../tasks/task-77%20-%20Declare-externals-with-a-startup-probe-vendor-pure-Python-packages-in-build-and-bucket-imports-in-check.md));
  doc-12 carries the 0.7.0 notes.
- **`@archont561/qgis-sdk`** — the next bridge minor is released from the same
  gate: the store core and the `./vue` and `./svelte` adapters next to
  `./react` ([TASK-69](../tasks/task-69%20-%20Replace-the-react-internals-with-a-framework-free-store-core-and-add-vue-and-svelte-adapters.md)); wire, plugin-description contract and
  `HOST_FINGERPRINT` unchanged, shown by `release.py verify-versions` and the
  fingerprint check; Tier 1 (vanilla, React) and Tier 2 (Vue, Svelte) stated
  in doc-13.
- **`@archont561/qgis-sdk-ui`** — first release ([TASK-70](../tasks/task-70%20-%20Create-qgis-sdk-ui-web-components-on-the-store-core-React-Vue-and-Svelte-wrappers-palette-tokens-and-Storybook.md)): the web
  components, the three wrappers, the palette tokens and the Storybook,
  gated and tagged (`ui-v*`) in the same run as the bridge, with
  `verify-versions` confirming its bridge peer range admits the released
  bridge. The docs site ([TASK-43](../tasks/task-43%20-%20Publish-a-Starlight-documentation-site-from-the-backlog-guides.md)) is live with the Storybook build.

## Version policy

0.7.0 is the next Python minor after 0.6.0; the bridge takes its next minor
and `qgis-sdk-ui` its first release from the same gate; none is a published
version until [TASK-32](../tasks/task-32%20-%20Prepare-and-qualify-0.7.0-release.md) is authorised. Experimental 0.x breaking changes
require a documented minor release; patches are compatible fixes. Prereleases
may use `0.7.0-rc.N` for a pipeline rehearsal (dry run, no uploads). Do not
bump manifests during planning. `qgis-sdk`, `@archont561/qgis-sdk` and
`@archont561/qgis-sdk-ui` carry **independent** versions, each derived from
its own commits and stamped by its own release tag ([decision-25](../decisions/decision-25%20-%20Version-each-package-independently-behind-a-shared-contract-version.md)); a shared
plugin-description contract version pairs the first two and a bridge peer
range ties the third to the second. Stable 1.0.0 requires a later explicit
API-stability decision.
