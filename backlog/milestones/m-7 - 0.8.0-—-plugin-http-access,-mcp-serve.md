## Description and exit criteria

Re-pointed on 2026-10-26: `m-7` held the deferred native-compute
reservation at 0.8.0; that moves to 0.9.0 and finally, when the hosts release took that number, to 1.1.0 as [m-12](m-12%20-%201.1.0-%E2%80%94-deferred-native-compute-feasibility-(tenta.md) and the
number goes to a release that ships. The runtime/agent decision-49 is
superseded. The boundary is now: an explicitly hosted, authenticated and
allowlisted **REST API in the plugin runtime** exposes selected plugin actions
and streams to clients outside QGIS, while **MCP lives in the developer CLI**
behind the `qgis-sdk-tools[mcp]` extra and never adapts that endpoint. The
runtime never binds a non-loopback address and never evaluates code.

Exit criteria, both required:

- **`qgis-sdk`** — `qgis-sdk-runtime`, `qgis-sdk-tools` and the `qgis-sdk`
  kit are released at 0.8.0 from one green gate ([TASK-78](../tasks/task-78%20-%20Prepare-and-qualify-0.8.0-release.md)): the explicitly
  hosted plugin HTTP API for allowlisted actions and streams, with the
  tools-side client and CLI ([TASK-74](../tasks/task-74%20-%20Expose-opted-in-plugin-actions-and-streams-over-an-explicitly-hosted-loopback-REST-API.md));
  `qgis-sdk mcp` on the `[mcp]` extra, exposing developer commands only and
  excluding plugin REST ([TASK-75](../tasks/task-75%20-%20Add-qgis-sdk-mcp-on-the-official-mcp-package-behind-the-mcp-extra.md)); a
  scripted MCP client and a live plugin client run at their public seams; UI
  snapshots with the
  `dev.ui` tools and the `ui_snapshot` fixture ([TASK-79](../tasks/task-79%20-%20Add-UI-snapshots-structured-tree-plus-screenshot-of-the-plugins-surfaces-dev.ui-agent-tools-and-the-ui_snapshot-fixture.md),
  [decision-51](../decisions/decision-51%20-%20Snapshot-the-plugins-own-surfaces-as-a-structured-tree-plus-screenshot-for-agents-and-tests.md)); the console reaches the same
  services and plugin handles through `qgis_sdk.console` ([TASK-73](../tasks/task-73%20-%20Add-qgis_sdk.console-ConsoleSession-over-the-curated-services-PluginHandle-and-PluginRuntime.algorithms.md),
  [decision-48](../decisions/decision-48%20-%20Give-the-QGIS-Python-console-the-curated-services-and-plugin-handles-never-iface.md)); declared externals probe at start with one
  message-bar error and a traceback, and pure-Python packages vendor
  through `build` ([TASK-77](../tasks/task-77%20-%20Declare-externals-with-a-startup-probe-vendor-pure-Python-packages-in-build-and-bucket-imports-in-check.md), [decision-50](../decisions/decision-50%20-%20Declare-third-party-Python-packages-as-externals-with-a-startup-probe-and-vendor-only-pure-Python-ones.md)); doc-12's 0.8.0 notes with the
  security model; the runtime manifest still declaring no dependencies.
- **`@archont561/qgis-sdk`** — **no release expected**: the transport
  speaks the envelopes the bridge already defines, so wire, plugin-
  description contract and `HOST_FINGERPRINT` do not move. The gate shows
  this (no file under `packages/qgis-sdk-typescript` changed, no npm version
  consumed) rather than assuming it.

## Version policy

0.8.0 is the next Python minor after 0.7.0 and is not a published version
until [TASK-78](../tasks/task-78%20-%20Prepare-and-qualify-0.8.0-release.md) is authorised. Experimental 0.x breaking changes require a
documented minor release; patches are compatible fixes. Prereleases may use
`0.8.0-rc.N` for a pipeline rehearsal (dry run, no uploads). Do not bump
manifests during planning. `qgis-sdk`, `@archont561/qgis-sdk` and
`@archont561/qgis-sdk-ui` carry **independent** versions, each derived from
its own commits and stamped by its own release tag ([decision-25](../decisions/decision-25%20-%20Version-each-package-independently-behind-a-shared-contract-version.md)); the two npm
packages are expected not to move in this milestone. Stable 1.0.0 requires a
later explicit API-stability decision.
