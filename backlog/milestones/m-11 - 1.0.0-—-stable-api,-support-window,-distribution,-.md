## Description and exit criteria

The readiness milestone. After 0.11.0 the SDK does everything the plan
says; 1.0.0 is the point where it also *promises* something. The white spots
named in the 2026-10-26 review each got a decision and a task here:
stability tiers, a generated public API inventory and a deprecation window
([decision-56](../decisions/decision-56%20-%20Define-1.0-API-stability-as-tiers-with-a-generated-public-API-inventory-and-a-one-minor-deprecation-window.md): [TASK-97](../tasks/task-97%20-%20Declare-API-stability-tiers-generate-the-public-API-inventory-add-release.py-verify-api-and-the-deprecated-API001-mechanism.md), [TASK-98](../tasks/task-98%20-%20Run-the-1.0-API-freeze-review-and-the-deprecation-sweep.md)); a support window of QGIS 4 LTR + latest on
Linux and Windows with a native CI leg per row, QGIS 3 out of scope
([decision-57](../decisions/decision-57%20-%20Support-QGIS-4-LTR-and-latest-on-Linux-and-Windows-with-a-native-CI-leg-per-row-and-keep-QGIS-3-out-of-scope.md): [TASK-99](../tasks/task-99%20-%20Add-the-native.yml-CI-leg-Windows-and-Linux-QGIS-from-locked-Pixi-environments-every-harness-matrix-transitions.md)); publishing to the official and private plugin
repositories, apps as conda packages, server deployment documented
([decision-58](../decisions/decision-58%20-%20Publish-plugins-to-the-official-QGIS-repository-from-the-tools-and-ship-standalone-apps-as-conda-packages.md): [TASK-100](../tasks/task-100%20-%20Add-qgis-sdk-publish-for-the-official-and-private-QGIS-plugin-repositories-with-the-PUB-check-rules.md), [TASK-101](../tasks/task-101%20-%20Ship-standalone-apps-as-conda-packages-from-build-target-app-and-document-server-deployment.md)); translations through Qt catalogues shared
with the page and accessible names ([decision-60](../decisions/decision-60%20-%20Translate-declared-strings-through-Qt-catalogues-shared-with-the-page-and-make-accessible-names-a-check-rule.md): [TASK-103](../tasks/task-103%20-%20Add-i18n-through-Qt-catalogues-shared-with-the-page-and-the-accessibility-rule-UI005.md)); settings
versioning, first-run/upgrade/reset hooks and runtime isolation ([decision-61](../decisions/decision-61%20-%20Version-plugin-settings-with-migrations-add-first-run-and-reset-hooks-and-keep-runtimes-isolated-per-plugin.md):
[TASK-104](../tasks/task-104%20-%20Version-plugin-settings-with-migrations-add-first-run-upgrade-and-reset-hooks-and-document-runtime-isolation.md)); one authority and threat model document with `check
--security` ([decision-62](../decisions/decision-62%20-%20Write-one-authority-and-threat-model-document-and-make-every-check-and-grant-refer-to-it.md): [TASK-105](../tasks/task-105%20-%20Write-doc-26-Authority-and-threat-model-SECURITY.md-and-qgis-sdk-check-security-with-SEC001.md)); `ctx.log`, crash capture and a
diagnostics bundle with no telemetry ([decision-63](../decisions/decision-63%20-%20Add-a-structured-plugin-log-service-crash-capture-into-it-and-a-diagnostics-bundle-with-no-telemetry.md): [TASK-106](../tasks/task-106%20-%20Add-ctx.log-crash-capture-into-it-the-Report-a-problem-surface-and-qgis-sdk-diagnose-with-no-telemetry.md)). Large payloads
([decision-59](../decisions/decision-59%20-%20Carry-large-and-binary-payloads-across-the-bridge-and-agent-boundaries-by-reference-with-bounded-pages-and-backpressure.md)) land earlier, in 0.10.0, because the services need them.

Exit criteria, all three required:

- **`qgis-sdk`** — released at 1.0.0 from one green gate ([TASK-107](../tasks/task-107%20-%20Prepare-and-qualify-1.0.0-release.md)): the
  reviewed inventory is the baseline `verify-api` diffs against; every
  stable symbol is marked; `publish`, `i18n`, settings migrations,
  `ctx.log`, `diagnose`, `check --security` exist and are documented;
  doc-22 and doc-26 are complete; the Windows QGIS row is qualified by
  `native.yml`.
- **`@archont561/qgis-sdk`** — released at its own next version from the
  same gate (1.0.0 if the owner so decides; the number is independent,
  decision-25): the generated client's public API is in the inventory and
  under the same tiers; `@deprecated` JSDoc for leftovers; wire unchanged
  since 0.10.0's protocol minor.
- **`@archont561/qgis-sdk-ui`** — released from the same gate with the
  accessibility and i18n additions; peer range confirmed.

## Version policy

1.0.0 is a SemVer planning target, not a published version, until its gate is
authorised, and it is the first release under [decision-56](../decisions/decision-56%20-%20Define-1.0-API-stability-as-tiers-with-a-generated-public-API-inventory-and-a-one-minor-deprecation-window.md): afterwards a
breaking change in a stable symbol requires a major. Prereleases may use
`1.0.0-rc.N` for a pipeline rehearsal (dry run, no uploads). Do not bump
manifests during planning. `qgis-sdk`, `@archont561/qgis-sdk` and
`@archont561/qgis-sdk-ui` carry **independent** versions, each derived from
its own commits and stamped by its own release tag ([decision-25](../decisions/decision-25%20-%20Version-each-package-independently-behind-a-shared-contract-version.md)); the bridge
and UI numbers at this gate are the owner's call, not implied by the Python
1.0.0.
