## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Integrate the versioned optional bridge with the dedicated code-generation, security and runtime tasks. Preserve all existing IPC/stream/resource acceptance criteria; raw native objects never cross the boundary.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Python and TypeScript validate the same contract fixtures.
- [ ] #2 Bridge surface is allowlisted and serializable; raw Qt/QGIS objects and arbitrary Python invocation are not exposed.
- [ ] #3 Bridge behavior can be tested without relying on live external services.
- [ ] #4 Generated operation-specific clients reject unknown operations and invalid inputs at compile time and validate responses at runtime; a manually asserted invoke<T> is not the public type-safety guarantee.
- [ ] #5 All calls pass through a narrow dispatcher with trusted host-bound view/origin/generation; forged payload caller IDs and direct-object paths cannot bypass per-view/resource authorization.
- [ ] #6 Invocation replies, subscriptions and operation streams have tested ordering, terminal/disposal/reconnect semantics and documented bounded buffering, gap/overflow policy and progress coalescing where applicable.
- [ ] #7 Resource release distinguishes borrowed layer handles from subscriptions and owned temporary outputs; releasing a borrowed handle never deletes the project layer, and repeated/in-flight close behavior is tested.
- [ ] #8 Client-local injected transports support typed scripted handlers, faults/events, isolated clients and leak checks; local abort/timeout is distinct from acknowledged host cancellation and never causes automatic unknown-outcome retries.
<!-- AC:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Tauri source review (2026-10-16): follow proposed decision-23 and doc-2 section 10. Verify native caller binding/QWebChannel behavior separately from mock tests. Public API names, stream limits and cancellation wire details remain open; no implementation is complete.

2026-10-24 (first slice: the host dispatch contract):
- What exists now: `qgis_sdk.bridge` (`protocol.py`, `dispatch.py`) is the QGIS-free host side of the transport - declared operations with an allowlist, envelopes, a narrow dispatcher, per-view bindings and generations, and JSON-safety on both the payload entering and the value leaving. The bridge package's `./bridge` subpath is the client side: a reply parser that refuses malformed replies and a `BridgeClient` correlated by call id over an injected transport.
- AC #2 (allowlisted and serializable) is met: an operation is a declared id and title bound to a handler, so there is no attribute path, no `getattr` and no way to reach an undeclared callable. `to_wire` refuses anything that is not JSON primitives, lists or string-keyed mappings, in both directions, so a Qt or QGIS object is refused at the boundary instead of being serialized by luck.
- AC #3 (testable without live services) is met: the dispatcher takes dictionaries and returns dictionaries. 21 Python tests cover it with no Qt, no QGIS and no browser.
- AC #5 (trusted view/origin/generation) is met: the binding is minted by the host, the payload is only data, so a forged `view_id` or `generation` claim changes nothing about who is calling. Authorization runs before the allowlist lookup, so a refused view cannot enumerate operations by watching which refusals differ, and `advance_generation` retires every live binding with `stale_generation`.
- AC #8 partially met (injected transports): `BridgeClient` takes a `WireTransport`; a local abort, a timeout and a closed client are three distinct errors, a timeout is reported as an unknown outcome and never retried, and late or unmatched replies are counted instead of being misdelivered to the next call.
- AC #1 met: `packages/qgis-sdk-bridge/tests/contracts/bridge/cases.json` is generated by `packages/qgis-sdk/scripts/generate_bridge_cases.py` from the real dispatcher, a Python test refuses drift from it, and the TypeScript test parses the same nine replies and must reach the same verdict.
- Still open, and not claimed: AC #4 (operation-specific generated clients, which TASK-17 owns), AC #6 (subscriptions and streams with ordering, bounded buffering and an explicit gap policy), AC #7 (borrowed handles versus subscriptions versus owned outputs), and the QWebChannel adapter that carries these envelopes over a real view.

2026-10-24 (CI evidence for the slice): run 40120350822 is green on PR #49. The cross-platform jobs report `bun test: 104 pass` on both Windows and macOS - 90 from before plus the 14 bridge tests this slice adds - and `pytest: 630 collected, 0 failed, 34 skipped` on Windows and `630 collected, 0 failed, 33 skipped` on macOS. The checks job also typechecks the new TypeScript under `strict` with `isolatedDeclarations`, which is where the loose fixture record type was caught.
