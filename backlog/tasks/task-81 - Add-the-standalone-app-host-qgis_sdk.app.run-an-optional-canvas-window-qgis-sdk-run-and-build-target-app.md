## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
decision-52 points 1, 3, 4. qgis_sdk.app.run(PluginClass, gui=False|True, argv=) owns QgsApplication (initQgis/exitQgis), builds the context without an iface, starts the runtime; gui=True provides a main window with a QgsMapCanvas so Desktop-style bindings and the later canvas service attach to the app's window; a web view in the app uses the same bridge; ctx.host reports app; qgis-sdk run launches with the discovered QGIS environment; build --target app produces a Python distribution with a console-script launcher under the same vendoring rules; scaffold --host app.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Bounded shutdown and loop inventory (decision-69 points 2 and 4). qgis_sdk.app.run(PluginClass, ..., grace=15.0) stops the job pump, stops the runtime, drains running jobs through jobs.quiesce() in a bounded loop, logs every job it abandons by name and settles it as cancelled, then calls exitQgis() exactly once. Every loop the host starts (job pump, dev reload watcher, the host's own timer) is named and enumerated when the runtime stops instead of being assumed stopped; ctx.host reports app.
App host, first slice (2026-10-31): the QGIS-free half of TASK-81 landed, plus the two targets that write nothing native. `qgis_sdk.app` is `run(app, *, gui=False, argv=None, grace=15.0, once=False, backend=None, title=None)`, `main(app, argv)` (the launcher entry: `--headless`/`--gui`, `--once`, `--grace`, `--title`, `--` for the toolkit, unknown options passed through, refusals on stderr with exit code 2), `quit()` and `current()`; `AppSession` owns init -> `backend.build` -> `PluginRuntime.start` -> `surface.bind` -> `exec`/`process_events` -> `stop`, and `QtAppBackend`/`QtAppSurface`/`AppWindowInterface`/`AppNotifications` in `qgis_sdk.adapters.app` are the only Qt in it (imported lazily, `QgisApplication` refused when one already exists, `QGIS_PREFIX_PATH` honoured, `initQgis`/`exitQgis` once). `qgis_sdk.core.loops` gives `NamedLoop`/`LoopState`/`LoopRegistry` (names unique per registry, stop in reverse start order, a loop that refuses to disarm is reported as still running) and `ctx.host` is `Host.APP` in both modes; `ctx.desktop` refuses by name and `ctx.ui` exists only with `gui=True` (decision-69 point 4: every loop the host starts carries a name - the job pump in a GUI app is `job-pump`). `AppSession.stop()` is the documented order: stop every recorded loop and name the ones that were running, wait up to `grace` for running jobs while ticking the job service, name and cancel the stragglers (they settle `cancelled`, no callback runs), close the surface, unload the runtime, `exit` once - `ShutdownReport` carries `stopped`/`loops`/`drained`/`abandoned`/`grace_seconds`/`elapsed`/`exited` with `summary()` and `to_json()` (decision-69 point 2). A start that fails after `init` still tears the toolkit down; a failure in `init` does not, because there is nothing to tear down. `QgisSdkAppError` (models, `code="app_refused"`) is the one refusal; the Qt backend turns a missing `qgis.core` into it, so a distribution installed into the wrong interpreter says which rather than raising `ImportError` from three frames down.

Evidence for AC 4 (`tests/test_app_session.py`, 34 pure tests, all green here): the report names every loop stopped, a job that finishes inside the window is drained and keeps its result, a job still running at the deadline is named, asked to stop and settles `cancelled`, the stop order is loops -> UI -> runtime -> exit, `stop()` twice reports once and exits once, a plugin with no jobs spends no time waiting, `exitQgis` is called exactly once on the success path and on a failed build and *not* at all when `init` failed, `run(once=True)` delivers instead of waiting, `quit()` reaches the running backend and refuses with nothing running, a second app in one process is refused, and the gap/deadline path runs on an injected clock and pause so no test sleeps. `qgis_sdk.testing.FakeAppBackend`/`FakeAppSurface`/`FakeLoop` drive all of it with no Qt.

AC 3 closed (2026-10-31). `examples/simple/simple/__main__.py` is the app entry (`from qgis_sdk.app import main as run_app`, `run_app(app, argv)`), `examples/simple/pyproject.toml` declares `hosts = ["desktop", "app"]`, and `tests/test_reference_example.py` pins the entry's shape, the two-host declaration and - in a subprocess with the example on `PYTHONPATH` - that the same declaration starts an `AppSession` whose `ctx.host` is `app`, whose `stop()` reports `exited` after exactly one `exit`, and whose action ids are the ones the Desktop dialog and the page drive. Doc-12 gained a full app-host section (the entry, the flags table, what the host offers and refuses, a Desktop-vs-app lifecycle table, the shutdown bound, the three ways to start one, `build --target app`'s layout, the scaffold, "the bridge is unchanged" and how to prove one without QGIS), a `qgis-sdk run` section before `build`, the `--target app` paragraph in the build section, the `--host app` paragraph in the scaffold section, and the "app host arrives with 0.9.0" line is now the present tense.

ACs 1 and 2 are written and blocked here, not done. `qgis-sdk run` exists (`_commands/_run.py`, `devtools.dev.plan_app`): it discovers QGIS like `dev`, runs the project's `<plugin>/__main__.py` as `-m <plugin>` in the project root with the install's bindings and the SDK's packages on the child's `PYTHONPATH`, falls back to a generated probe that imports `[tool.qgis-sdk] plugin` and calls the same `qgis_sdk.app.main` for a project without an entry, forwards `--headless`/`--once`/`--grace`/`--title`, sets the offscreen platform when there is no display, writes nothing into the project and removes its temporary directory - `tests/test_app_run.py` (12) pins the plan and the command over `FakeCliRuntime`. `build --target app` exists (`qgis_sdk_tools.bundle.app.build_app` + `AppBuildResult`, `--target plugin|app`, default `plugin` unchanged): a pip-installable directory with the plugin staged and imports rewritten, the runtime vendored at `<plugin>._vendor/qgis_sdk` with NOTICE and the same externals probe/`vendor` handling as the ZIP, a generated `<plugin>/_launcher.py` (probes the declared externals, then `qgis_sdk.app.main`), a `pyproject.toml` whose `[project.scripts]` is the console script and whose `package-data` lists the runtime's data files (Processing catalogue, reference styles) file by file. `tests/test_app_build.py` (18) is the build-install harness: it writes the distribution, `pip install --no-deps --no-build-isolation --prefix` into a throwaway prefix, and runs the installed console script - the installed launcher parses its flags and exits 2 on a bad one, and on this QGIS-free host it refuses with "this interpreter cannot import PyQGIS" and exit 2 instead of a traceback. `scaffold --host app` is in too (`HOSTS` gained `app`, `<plugin>/__main__.py` written, an `FakeAppBackend` starter test, `--ui native`/`--algorithm` allowed, `--web` refused by name; HOST001 now accepts `app` as a windowed host, so a `@toolbar` on an app-only project is not a finding - HOST002 still fires for a server hook on either). Still open on AC 1: the offscreen native test (`tests/test_app_native.py`) exists - it starts the host in a child interpreter with `QT_QPA_PLATFORM=offscreen` and asserts the `QMainWindow`, its `QgsMapCanvas`, the toolbar action and menu, and the `Dialog`/`Dock` a `ctx.ui.open` produced - but this workspace has no PyQGIS, so it skips; it has to be run on the `QGIS 3.44 LTS` row (or a 4.x install) before the criterion is claimed. Still open on AC 2: the same is true of the installed launcher actually starting the app (`--headless --once` in that child interpreter), and the Windows row stays recorded-or-blocked per TASK-33.
Review of the native seams (2026-10-31): three corrections. `AppBackend.init` takes `gui` because Qt fixes `GUIenabled` when `QgsApplication` is constructed, so `run(app)` creates the application without a window system and `run(app, gui=True)` with one. `AppWindowInterface` places menu entries the way `iface` does - `addPluginToMenu(name, action)` opens a submenu of that name under its family menu, and removing the last entry prunes the submenu and then the family menu - so `@menu("Plugins/Field tools")` reads the same in an app and in QGIS. A full run under `--cov` failed in `test_the_session_budget_answers_503_with_its_code`: each drained item posted the next turn, so a host whose `post` runs the callback inline (the tests' `lambda callback: callback()`) nested one drain frame per queued request and a 64-stream backlog ended in a `RecursionError` raised inside coverage; `GuiQueue._drain` now notices the re-entry and lets the finishing item's loop take the next one, so the stack stays flat (regression test: 200 queued requests at one depth). `GuiQueue.call` also stops trusting deque membership when a pickup deadline expires: a request the owner already took is answered rather than reported as never picked up.

Green gate (2026-10-31, PR #155, run 41157232493): every job passed - `Linux checks` (`-m "native and not smoke"`, which includes `test_app_native.py` on QGIS 4.2.3 / PyQt6 / Python 3.14 offscreen), `QGIS 3.44 LTS`, `Linux coverage` (pure layer, 91.5%), cross-platform macOS and Windows, `build and check the site`. AC 1 is therefore proven on a native row: headless the process is a real `QgsApplication`, `ctx.host` is `app`, the project/settings/jobs services answer and `ctx.desktop`/`ctx.ui` refuse by name; with `gui=True` the window is a `QMainWindow` carrying the canvas, the `@toolbar` action, the `Plugins/Native app` submenu, and the `Dialog`/`Dock` surfaces open inside it, with the shutdown report naming `job-pump` and `exited` true. Getting there cost four CI-only defects, all fixed in this PR: PyQt6's `QgsApplication` takes `list[bytes]` (a list of str raises `TypeError: expected bytes, str found`); the probe's child interpreter needed `layers.qgis_bindings()` on its PYTHONPATH because pixi, Debian and Ubuntu keep PyQGIS in `share/qgis/python` off `sys.path`; a `@job` in the probe named its first parameter `ctx` without annotating `WorkerContext`; and the suite's `pip install --prefix` harness cannot run in a Pixi interpreter, which has no pip, so those two tests now skip with that reason and keep their evidence on the macOS/Windows rows. Two still open for AC 2: `qgis-sdk run` end to end against a discovered QGIS is not exercised by a native test (only the plan - argv, environment, probe lifetime - is, in `test_app_run.py`), and the Windows half stays recorded as unqualified in `targets.py` per TASK-33. Covered by `Linux checks` means `AppSession` starts the toolkit, not the command line wrapper.
