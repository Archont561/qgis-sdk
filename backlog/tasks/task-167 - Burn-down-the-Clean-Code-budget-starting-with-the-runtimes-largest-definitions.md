## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-166 makes the Clean Code metrics a gate by freezing today's 939 findings as `clean_code_budget.json`. This task is the other half: the budget only ratchets if somebody turns the ratchet, and the largest entries are the ones worth turning first, because they are the definitions a change to the runtime has to read before it can be changed safely. Each slice extracts cohesive helpers behind unchanged behaviour and lowers the budget in the same commit; the budget diff is the evidence, since nothing else in the repository records that a function got shorter.

**Slice 3 (landed): the dispatcher, split into the four things a call can be.** 882 -> 866 findings; `bridge/dispatch.py` goes from 17 findings to 2, and the 756-line, 35-method `Dispatcher` is now a 197-line, 21-method façade over a new `bridge/endpoint/` package (5 modules, 1045 lines, all clean on their first commit).

The cut is the order the endpoint decides in, one role per module: `_registry` holds what may be called, `_views` who may call it (bindings, generations, the handshake and its contract), `_streams` what is already running (a `_Book` of subscriptions and the calls that drive it), `_calls` the invocation itself plus the release call beside it. `_wire` owns what crosses the wire and the checks a value passes first; `_refusals` owns the one way a call stops.

That last module is the idea the six long methods needed. Each of them was a chain of `if <bad>: return failure(...)` - `dispatch` alone had 19 returns and 15 branches - so the happy path was unreadable. A refusal is not an error, it is the reply the caller gets, so a check now raises `QgisSdkRefusal` carrying that reply and `Dispatcher.dispatch` is the single place that catches it: `_invoke_reply` and `_subscribe_reply` read as the list of steps they are, with one return and no branches. The exception carries the `QgisSdk` prefix for the reason `test_error_names.py` gives - nothing in the runtime may define an unprefixed exception class, because one day one of them reaches user code.

Two findings are left in `dispatch.py` and both are deliberate, not leftover:

**Slice 7 (landed): the queue, split by the three policies one lock guards.** 837 -> 834 findings, 263 -> 262 files; `http/_queue.py` leaves the budget entirely (CC201 232-line `GuiQueue`, CC101 and CC303 on `_drain_one` -> 0).

This one is not the same shape as the five definitions before it. `GuiQueue` is a lock discipline: the request deque, the cleanups, the owner's current item and the scheduled flag are read and written together, so splitting them into objects with a lock each would only mean acquiring several of them in a fixed order. The cut is therefore by *policy*, and the lock stays on the queue as the one thing that covers all three:

* **`_Cleanups`** - the deferred work, one entry per session. Its retention rule is the reason it exists: unlike a request, a cleanup is not discarded when the queue fills or a post is rejected, so it is retried until the host accepts it. `add` / `take` / `clear` / `__bool__`.
* **`_Turn`** - what the owner thread is running and what it owes when it stops: `start(item)`, `finish(item, value, error)` returning the owed cleanups, `owe(fn)`, and `busy`. This collapsed `_active` into `current is not None`: the flag was only ever set and cleared with the item it described, so it could not say anything the item did not, and one fewer flag is one fewer way for the two to disagree.
* **`_refuse_all(items, error)`** and **`_settle_late(items, work, deadline)`** are module functions over the deque, because each is one policy applied to a queue element rather than behaviour of the queue: fail every waiting caller, and settle a request whose pickup deadline has just expired. The second is what the 22-line `_adopt_late` used to be, with the method left as a three-line delegator that takes the lock.

`_drain_one` (41 lines, 11 branches) is now three decisions: `_take` claims the next item under the lock, cleanups before requests; `_drain_one` runs it, settles it and runs the cleanups the owner owed; `_next_turn` posts the next turn unless one is already on its way. The flat-stack guard in `_drain` and the retry timer are untouched - they are the subtle half of this module and nothing about the split needed them to move.

**The three white-box tests pinned the shape, and they still pass untouched.** `test_a_backlog_is_drained_flat_instead_of_one_frame_per_request` appends to `queue._items` and calls `queue._drain()`; `test_a_request_taken_as_the_deadline_expires_is_answered_not_dropped` replaces `queue._items` with a deque subclass whose `remove` hands the item over mid-deadline; `test_a_request_nobody_picks_up_is_still_reported` asserts `len(queue._items) == 0`. So `_items` stays a `deque` attribute of `GuiQueue` and `_drain` stays its method - which is the right call anyway, those two tests being the only statement in the tree of the late-pickup race. Nothing was rewritten: the four `GuiQueue` tests and the whole `test_plugin_rest` / `test_server_jobs` / `test_app_session` set passed unchanged on the first run.

`GuiQueue` is now exactly 200 lines, which passes the rule and is worth saying out loud: the next line added to it wants an extraction rather than a bigger number. Coverage on the module is 90% across the three server suites (85% before the split), with the same gaps as before - the rejected-post retry path, the full-queue refusal, the cancelled-head sweep and close-with-a-timer-armed have never been exercised by a test.

**Tests.** 3002 passed, 129 skipped with the two environmental `test_app_build` failures; `tests/scripts` 332 passed. ruff, alint and the clean-code gate clean.

**Slice 8 (landed): the Processing adapter, split by what a toolbox run touches.** 834 -> 817 findings; `adapters/qgis/processing.py` goes from 18 findings to 1, and the 288-line, 17-method `_BridgeAlgorithm` with its 69-line `_parameter` and 81-line `_value` is gone: it is a 13-method class over nine modules that each hold one part of a run.

Both directions and both ends of a run read it, so a kind added to `qgis_sdk.models` lands here once.

The 13-branch, 15-return `_parameter` is a `_BUILDERS` table of ten rows over thirteen kinds: the plain kinds share `_build_plain`, and each row that needed something extra (a field's parent layer, a file's filter, a range's bounds and whether it is integral, a colour's opacity, a layer's source type) is a named builder of two to eight lines.
